# 許願板的 emoji 用現成 picker，這是這個 repo 的第一個第三方 UI 相依

許願板（web-spec §12）讓大家對願望與留言按 emoji，而且**可以按任何一顆**，
不是從固定集合裡挑。決定是引進 **`emoji-picker-react`，釘死版本，並用 `React.lazy`
動態載入**。

這值得一張 ADR，是因為在這個決定之前 `web/` 的 runtime 相依只有三個：
`react`、`react-dom`、`react-router-dom`。**沒有 UI 套件、沒有 CSS 框架**，
所有元件都是手寫的 `.tsx` + `.css`。後面來的人看到 `package.json` 裡冒出一個
帶資產的 UI 套件，會合理地懷疑是誰順手加的 —— 不是，是這裡決定的。

## Considered Options

**手寫一層很薄的：一排常用六顆 ＋ 一顆「其他…」開一個只收一個字元的輸入框。**
手機會跳出系統 emoji 鍵盤，桌面是 Win+`.` / Ctrl+Cmd+Space。任何 emoji 都按得到，
成本幾乎為零，沒有相依。**這是被放棄的那條**，放棄的理由是選擇範圍與熟悉的操作感
（Teams / Slack 的既有語彙，不用學）值得這個相依。

**固定一小組（🧋 👍 😭 🎉）。** 最省，而且那幾顆在這個專案裡是**設計過的語彙**
（🧋 不是隨便一顆 emoji）。picker 會把這個稀釋掉 —— 這是這個決定真正的代價，
不是體積。

**`emoji-mart`。** 更完整（搜尋、最近使用、膚色），但要配 `@emoji-mart/data`，
兩個套件、體積明顯更大。許願板是鷹架，不值得。

## Consequences

- **釘版本。** 這個 repo 對 `ruff==0.16.1`、CLI `2.1.278` 都是這樣做的，
  這裡不開特例。升版要跟著看渲染結果。
- **必須 `React.lazy`。** 它不能進主 bundle —— 提交頁與 job 詳情頁的首屏不該為了一個
  點開才用的選單變胖。
- **這個相依跟許願板一樣帶著下架條件。** 許願板是試玩期鷹架（web-spec §12），
  Phase 2 驗完或連續 30 天無新內容就移除。**拆牆的時候要一起檢查這個套件還有沒有
  別的地方在用** —— 如果那時它已經被別處引用，就不再是「順手拆掉」，
  而是一個要重新決定的東西。這句話寫在這裡，是因為到那天沒有人會記得它曾經是暫時的。
- **🧋 那顆的語彙稀釋掉了，而我們接受。** 排行榜與欠債通知（web-spec §9）仍然只用
  固定那幾顆，玩心預算主要花在那裡；許願板上按什麼是大家的事。
