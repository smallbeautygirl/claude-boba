# claude-boba Web 規格 v0.1

> 系統規格在 [../SPEC.md](../SPEC.md)。這份只講**使用者看到什麼**：畫面、狀態、文案。
> 兩份分開是刻意的 —— 混在一起會互相稀釋。

---

## 0. 這份文件的讀法

Web 是這個產品本身。後端只是讓它能跑。

TA 是 **BD / PM 與 RD 混合**（SPEC §1）。前者九成不寫程式、用 claude.ai 或 Claude app；
後者用 Claude Code。**兩種人的路徑都要是第一級公民**，不能有一邊是「進階功能」。

---

## 1. 技術選型

**React 19 + Vite + TypeScript**，前後端分離，Hub 提供 REST + SSE。

選它不是因為技術上最省，而是因為 `lighthouse-saas-api` 的 `observ-event-dashboard` 與
`easy_visionai_tools` 都是這一套 —— 團隊既有經驗直接適用，交接時不用多學一種東西。

**即時更新走 SSE，但必須有 poll fallback。** 連線中斷就退回每 5 秒 poll；
使用者不該察覺差別。SSE 的內容見 §4。

---

## 2. 畫面清單

六個，全做。

| # | 畫面 | 給誰 | 重點 |
|---|---|---|---|
| 1 | **提交 job** | 借用者 | 登入後的首頁。單頁，不分步驟 |
| 2 | **我的 job** | 借用者 | 列表 + 狀態 |
| 3 | **Job 詳情** | 借用者 | 即時串流、輸出下載、花費 |
| 4 | **帳本** | 雙方 | 我欠誰 / 誰欠我，出租者在這裡結清 |
| 5 | **排行榜** | 全部 | 欠債王。產品靈魂 |
| 6 | **我來代跑** | 出租者 | 出借條件、出借帳號與用量、**緊急停止** |

第 6 個最容易被漏掉，但出租者是供給側 —— **沒有他們就沒有服務**。

## 3. 提交頁（首頁）

登入後直接落在這裡。使用情境是「我額度爆了，很急」，所以最短路徑優先；
帳本與排行榜放導覽列，想看的人自己去。

**單頁，由上而下：**

```
┌─ 對話內容 ─────────────────────────────┐
│ [ 大文字框：貼上你的對話 ]              │
│ 或 [ 上傳 .jsonl ]  ← Claude Code 使用者 │
└────────────────────────────────────────┘
  ⚠️ 貼上的對話會被「讀過」，但 Claude 不會真的記得當時的環境。
     用 Claude Code 的話，上傳 .jsonl 可以真正接續。

[ 附件（選填） ]

出租者： [ 自動（推薦） ▾ ]
Model：  [ Sonnet（預設） ▾ ]

☐ 我了解 Vivian 技術上可以看到我送出的內容

                              [ 送出 ]
```

### 上傳 `.jsonl`（已實作）

**分界是工具，不是職稱。** 不要寫成「RD 上傳、BD/PM 貼上」—— 剛好用過
Claude Code 的 PM 就有 `.jsonl`，照職稱寫會讓他以為這功能不關他的事。
畫面上要問的是「這個對話是在你電腦上用 Claude Code 跑的嗎」。

**不要在畫面上叫使用者判斷自己屬於哪一類。** 這段文案照職稱寫過、照 app 名稱
寫過、照「session 存在哪」寫過，三次都錯 —— 那需要使用者（和寫文案的人）懂產品
架構，而產品架構會變。

改成讓指令當測試：`ls -t ~/.claude/projects/*/*.jsonl | head -5`，有東西就上傳，
沒有就貼上。這行之所以夠用，是因為 **Cowork 的 local session 也寫在
`~/.claude/projects/`**，跟 CLI 同一棵樹（SPEC §11 spike #7 實測）。

| 來源 | 本機有 transcript？ |
|---|---|
| 終端機 `claude`、VS Code / JetBrains 擴充、Desktop 的 Code 分頁 | ✅ |
| Cowork **local** session | ✅ 同一棵樹。metadata 另放，靠 `cliSessionId` 對應 |
| Cowork **cloud** session | ❌ 跑在 Anthropic 伺服器，session 存帳號 |
| Chat、claude.ai、手機 | ❌ |

**而「沒有 transcript」不是少了一個功能。** 那些對話跑在伺服器上，不存在可以餵進
`--resume` 的匯出格式；就算生得出一個檔案，裝的資訊也跟貼上一模一樣。

而**對 BD/PM 來說，貼上損失的東西遠比對 RD 少**：`--resume` 比貼上多帶的是
工具呼叫的結果與本機檔案狀態，而 claude.ai 的對話本來就沒有這些。他們真正
帶不過來的只有**附件**（見〈不做／還沒做〉）。

也不要想「幫他們合成一份」：`--resume` 比貼上多帶的不是檔案格式，是工具呼叫的
結果與檔案狀態。聊天對話裡沒有這些，所以合成出來的 transcript 裝的資訊跟貼上
一模一樣 —— 花工程換零收益。

還有一件事讓這個落差只存在於**第一跳**：job 跑完 worker 會把自己的 transcript
存起來，所以第二輪之後用「接著問」，不論來源都是真的續跑。

因此提交頁的說明要分兩種來源講，而且**指示要給到能貼進終端機的程度**。
「去 `~/.claude/projects/` 找」不是可執行的指示 —— 那底下一個專案一個資料夾，
隨便一台開發機就上百個 session 檔，檔名還是看不出內容的 session id。

檔案由瀏覽器直接 PUT 進 MinIO（`POST /api/uploads/transcript` 換一張預簽票），
不經過 Hub。Hub 在建立 job 時才驗：**key 的 prefix 必須是呼叫者自己的**、
存在、≤ 50 MB、開頭幾行是 JSON。第一項是存取控制 —— 不驗的話任何人都能把
`transcript_key` 指到別人 job 的 transcript。

**帶了檔案之後，文字框的意思會變。** 上下文在檔案裡，那個框要填的是
「接下來做什麼」，標題與提示都跟著換：

| | 沒有檔案 | 有檔案 |
|---|---|---|
| 標題 | 對話內容 | 接下來要它做什麼 |
| 提示 | ⚠️ 貼上的對話會被「讀過」，但 Claude 不會真的記得當時的環境 | ✅ 這是真的續跑，出租者那邊用 `--resume` 接上 |

**檔案一選好就上傳，不是等按下送出。** 50 MB 的檔案在按下送出之後才開始傳，
使用者會盯著一顆沒反應的按鈕。大小與格式也是前端先擋一次 —— 不要讓人
上傳三分鐘才說太大。


### 出租者下拉

預設「自動（推薦）」，展開後列出線上 worker 及其差異：

```
├ 自動（推薦）
├ Vivian   🟢 線上 · 🔒 白名單網路 · 額度 🟢 充裕 · Sonnet/Haiku
└ Alex     🟢 線上 · 🌐 開放網路 · 額度 🟡 快滿了 · Sonnet/Haiku/Opus
```

三件事一次解決：§7 的「改送」有地方去、RD 知道該挑開放網路的、
而額度紅綠燈讓借用者對別人的餘裕有感 —— **這個訊號本身就是社交剎車**。

**額度只顯示紅綠燈，不顯示百分比。** 精確數字會讓人盤算「他還有 66%，再送一個沒差」，
把人情變成資源計算。模糊剛好：足夠傳達分寸，不足以精算。

> ⚠️ **2026-09-22：這顆燈的語意變了。** 一位出租者現在可以有多個**出借帳號**
> （SPEC §4.12），而燈只有一顆 —— 它取那個人底下**最充裕**的帳號。
> 所以它回答的問題從「他的帳號還剩多少」變成「**他的池子現在接不接得動**」，
> 而那正是借用者真正在問的事（派單也是挑 utilization 低的那個去跑）。
>
> 不取平均：個人帳號 10%、公司帳號 90% 平均出來的「🟡 快滿了」，
> 兩個帳號都不是那個狀態。
>
> **這條「不顯示百分比」只約束借用者看別人。** 出租者看自己的精確數字一直是
> 允許的（`_view()` 裡的 `if owner:`），見 §8。

### 指令（2026-09-22）

輸入列上那顆 `/` 已經在了（`web/src/Composer.tsx`、`CommandPicker.tsx`），
點開是分好組的中文動詞短句。**畫面上不會出現「skill」這個詞** —— 那要懂產品架構
才看得懂，而 §3 前面那段已經記取過三次同樣的教訓。

**問題不是描述不夠，是 `/` 不會被發現。** 知道 `/` 是什麼的人不需要被告知；
不知道的人（正是這個功能為他做的那個人）永遠不會點它。

**所以：文字框空著的時候，框內露出四個 chip，一打字就收掉。**

```
┌─ 對話內容 ─────────────────────────────┐
│                                         │
│  [做簡報] [做表格] [畫圖表] [這裡能做什麼] │
└────────────────────────────────────────┘
```

- **不預設展開整份清單**：五組十九項攤在一個「額度爆了、很急」的人面前，
  違反這一頁「最短路徑優先」。
- **不另開一塊常駐區**：會跟輸入列搶位置，而 CONTEXT.md 已經定死「輸入列裡只放動作」——
  兩個地方管同一件事就是下一個 bug。
- **不依角色切換**（RD 看到工程那組）：要求系統判斷誰是 RD，而這一頁已經錯過三次。
- **為什麼是這四個**：前三個是 BD/PM 用自己的 Claude app **做不到**的事（產不出檔案）。
  第四個 `這裡能做什麼` 排最後，它是逃生門 —— 點了它，`/` 這個手勢本身就被教會了。

**清單顯示的是聯集，但選了指令會收窄派單範圍**（SPEC §4.13）。
指令因此是〈出租者下拉〉那三項差異之外的**第四項** —— 不同代跑者會的不一樣。
選了沒人能跑的指令，要當場講（「目前線上沒有人能跑這個」），不能默默排隊。

### 缺服務憑證時（2026-09-22）

有些指令要連外部服務（第一個是 Observ），需要委託者自己的**服務憑證**（ADR-0002）。

**在他選了那個指令的當下、原地要，不做前置設定頁。** 要求使用者先逛設定頁才知道
自己缺什麼，正是這個功能要解決的那個失敗：「不會設 `.env`」的本質是
**得先去別的地方把東西配好才能開始**。原地問的好處是它帶著上下文 ——
他此刻知道自己為什麼需要它。

交一次就存著，之後同一個指令不再問。送出時 hub 會先驗一次，**驗不過就不收單** ——
不能讓貼錯的憑證燒掉代跑者的額度。驗不過的訊息要講清楚是憑證的問題，
不要讓人以為是指令壞了。

### Model 選單

顯示的是「站台白名單 ∩ 該出租者白名單」的交集（SPEC §9）。**預設 Sonnet**。

預設不是 Opus，因為 BD/PM 不會知道差別、會直接送出，而那等於每個 job 貴 2.5 倍。
想要更好的人自己會改。

### 隱私勾選

**必須主動勾選，不能預設打勾。** 預設打勾的同意等於沒有揭露，
會架空 SPEC §4.3 定下的誠實原則。

> ☐ 我了解 **<出租者> 技術上可以看到我送出的內容**
>
> 這個 job 會在對方的電腦上執行。系統預設不讓出租者查看內容，但技術上他有能力看到。
> 請不要送出公司機密、客戶個資，或任何你不希望被對方看到的東西。

### 上傳限制

單一 transcript **50 MB**、附件合計 **50 MB**、單一 job 上限 **100 MB**。**前端先擋**，
不要讓人上傳三分鐘才說太大。

依據：一句 `"pong"` 的 transcript 就 224 KB（系統提示與工具定義佔絕大部分），
真實 RD session 估 10–50 MB。超過 50 MB 的 session，`--resume` 本身也會慢到不實用。

## 4. Job 詳情：等待與串流

### 心智模型：可以離開

Job 可能跑 10 分鐘。使用者**可以留在頁面看，也可以關掉分頁**，
跑完 Teams 會通知。明講這件事，等待感就消失了。

### 串流內容

worker 用 `--output-format stream-json`，事件經 Hub 轉發給瀏覽器。顯示到**工具名稱**這一層：

```
🟢 Vivian 接下了這個 job
   正在讀取 requirements.txt
   正在執行指令
   💭 思考中…                        ← 預設收合，可展開
   
   「我看了你的需求，建議分成三個階段…」
   
   ⏱ 已執行 3 分 12 秒
```

- **顯示工具名稱與檔名，不顯示指令全文。** 理由不是隱私（那是借用者自己的內容），
  是畫面會被洗版 —— 一個 bash 指令可能二十行。
- **thinking 預設收合。** 對 BD/PM 是噪音，對 RD 有用，收合可展開兩邊都照顧。
- **不要顯示進度條。** 我們沒有進度資料，進度條會撒謊 —— 走到 70% 會讓人以為快好了。
  顯示「已執行 3 分 12 秒」誠實得多，數字變大時使用者自己會決定要不要走。

### 離開後回來

**Hub 保存整份事件流。** 重新進入頁面時先重播歷史，再接上即時串流。

這也是 SSE 斷線重連的機制：重連時帶上「我看到第幾個事件」，Hub 從那裡續傳。
成本不高 —— 事件流本來就要存進 MinIO 當明細（SPEC §7）。

## 5. 失敗的呈現

三類，揭露程度不同。**不論哪一類都不計債**（SPEC §5）。

| 類型 | 例子 | 給使用者看什麼 |
|---|---|---|
| **可修復** | 檔太大、白名單擋到、逾時、超出預算上限 | 完整原因 + 明確下一步 |
| **系統問題** | worker 掛了、MinIO 寫入失敗、Observ token 過期 | 「系統問題，已記錄」+ job id |
| **Claude 本身** | API 錯誤、模型拒答、rate limit | 原始訊息（那是 Claude 給使用者的，不是我們的） |

### 分類做在後端，前端只負責渲染

判斷寫在 `hub/app/failures.py`，job 詳情的 API 會回一個 `failure` 物件：

```json
{
  "kind": "fixable | system | claude",
  "title": "超過時間上限，已中止",
  "hint": "把要做的事拆小一點再送一次。這次不計債。",
  "show_detail": true,
  "blocked_by_network": false
}
```

前端的責任只有三件：顯示 `title`、顯示 `hint`（若有）、以及**只在
`show_detail` 為真時**才顯示 `error_detail`。系統問題的 stderr 對使用者
沒有意義，也幫不上忙。

放後端的理由：同一份判斷未來 Teams 通知也要用，而且前端會改版 ——
把規則放在會被重寫的地方等於會遺失。

### 白名單擋到要特別處理

這會是 RD 最常撞的牆。若只寫「執行失敗」，他們會以為工具壞了。
後端已經會認出這種情況並回 `blocked_by_network: true`。

> ⚠️ 這個 job 嘗試連線到 `pypi.org`，但 Vivian 的 worker 是白名單網路模式。
>
> 〔改送給 Alex（開放網路）〕

**那個按鈕是重點**，不是那句話。

> 🚧 按鈕還沒實作 —— 目前只有一台 worker，按了沒地方送。
> 有第二台之後再做，後端的 `blocked_by_network` 已經備好。

## 6. 帳本與結清

### 結清由債主按

出租者在帳本頁每一筆旁邊按「他還了」即結清（SPEC §4.8）。
**Teams 通知裡也要能直接按** —— 債主通常懶得特地開網頁。

借用者這邊有「我請過了，戳他確認」，把催促責任放在欠債的人身上。

### 債務不設到期日，但顯示欠了幾天

比自動勾銷更有社交壓力，也更好笑。

## 7. 排行榜

**欠債王 = 未結清筆數最多的人**，同時顯示累計金額。**時間範圍是全部，不按月重置。**

為什麼不用累計金額排：一個跑了一次大 job、當天就請客的人會高居榜首 —— 那是在懲罰使用者。
用未結清筆數的話，榜首是那個欠了五杯飲料三個禮拜的人，**那才是大家想調侃的對象**。

不重置是因為這個系統的核心資產就是「債會一直記著」。

只顯示聚合數字，**不做動態牆** —— 「誰跟誰借了什麼」本身就是資訊，會踩到 SPEC §4.3 的隱私線。

## 8. 我來代跑（出租者）

極簡：一張狀態卡 + 設定 + 停止鈕。

```
┌──────────────────────────────────┐
│ 🟢 線上 · 最後回報 12 秒前        │
│ 五小時窗口 🟢 充裕                │
│ 今天跑了 3 個 job · 借出 $4.20    │
│                                  │
│ 執行中：job #a3f2（BD Kevin）     │
│         已執行 2 分 08 秒         │
│         〔停止〕                  │
│                                  │
│ 〔暫停接單〕                      │
└──────────────────────────────────┘
```

設定：單次預算上限、網路模式、可用 model。**並行數不在這裡** ——
它是每個出借帳號的物理性質，不是使用者在表達意願的旋鈕（SPEC §4.12）。

### 出借帳號與額度面板（2026-09-22）

SPEC §4.12 之後這頁要列出**出借帳號**。一個帳號的時候也列 —— 那一列不是為了
多帳號而存在，它是放用量的地方：

```
你的出借帳號
┌──────────────────────────────────────────────┐
│ 個人 Max                                     │
│ 五小時窗  ▓▓▓░░░░░░░  34%   1 小時後重置      │
│ 七天窗    ▓▓▓░░░░░░░  30%   2 天後重置        │
│ 資料為 3 分鐘前                               │
├──────────────────────────────────────────────┤
│ 公司帳號（批准者：<填的那句話>）   ⚠️ 需重新授權 │
│ 這個帳號目前不接單，其他帳號照常                │
└──────────────────────────────────────────────┘
〔再授權一個帳號〕
```

**百分比與重置倒數只給本人，不給借用者。** 理由跟 §3 那條完全一樣：
知道「他一小時後就滿血」會直接變成「那我現在多送幾個」。

**過期的數字不顯示成即時的。** 標「資料為 X 前」，太舊就顯示「不知道」——
出租者自己在別的地方也在燒同一個帳號，站台不會知道，這時掛一個理直氣壯的
34% 比不顯示更糟。資料怎麼來、多久問一次，見 SPEC §11 spike #10。

**其中一個帳號的 token 失效時，只有那個帳號停止接單，其他照跑。**
job 不受影響（另一個帳號會接）。這是「出借帳號」這個概念在整個 UI 裡
唯一露臉的地方 —— 借用者那側從頭到尾看不到它。

**再授權一次已經有 token 的帳號會換掉它。** 那顆按鈕旁邊要講清楚：
舊的那組站台不會再用，但它在 Claude 那邊仍然有效到期滿。
不擋（換帳號、token 被撤銷後重授權都是正常需求），但不能無聲。

### 停止的範圍

**停當前 job + 可暫停接單。不做「封鎖特定借用者」。**

封鎖在人情系統裡是社交核彈 —— 一旦按鈕存在，沒按也會有人猜想。
而它要解決的問題（某人一直濫用）在 10 人團隊裡，用講的比用系統快得多。

### 停止的後端已完成，UI 待接

`POST /api/jobs/{id}/stop`，body `{ "note": "..." }`（note 選填）。
job 詳情的 `can_stop` 欄位告訴前端現在這個人能不能按 —— 只有**正在跑這個
job 的出租者**能停，而且它必須還在執行中。

Hub 會立刻把狀態改成 `cancelled`，不等 worker 確認 —— 否則按了之後畫面
沒反應。真正殺掉容器的是 worker，它在下一次回報時從回應裡收到 cancel。

> 📌 worker 每 3 秒會空跑一次回報，即使 job 沒有任何輸出。沒有這個心跳，
> 停止只在 job 還在吐事件時才有效 —— 而最需要停止的正是安靜卡住的那種。

### 停止時可選填一句話

這個欄位的價值高於整個停止功能：

> ❌ 「你的 job 已被出租者終止。」
> ✅ 「Vivian 終止了你的 job：『這個看起來會跑很久，我等下要開會，晚點再幫你跑』」

**沒有那句話，停止會被讀成拒絕。**

## 9. 語氣

**平常玩笑感，三個地方切換成完全正經：**

1. **隱私警告** —— 用可愛的語氣講「他看得到你的內容」，人會不當一回事
2. **錯誤訊息** —— 使用者要的是「發生什麼事、我該怎麼辦」，不是俏皮話
3. **金額** —— 顯示 US$3.20 就顯示 US$3.20，不要模糊化

其餘全部可以玩。**這個對比本身就是設計**：正因為平常很鬆，嚴肅的地方才顯得嚴肅。
如果整個介面都在搞笑，隱私警告就會被當成裝飾。

## 10. 不做的事

- **儀表板首頁** —— 為每天會用的工具設計的，而這個工具最好的狀態是「大家很少需要用到」
- **互動式出租者引導** —— 工程量遠大於價值。出租者只有幾個人、都是 RD，
  一頁寫清楚的安裝文件加一個 `install.sh` 就夠
- **獨立的新手說明頁** —— 沒人會讀。說明要長在提交頁本身（§3 的那些文案就是在做這件事）
- **動態牆** —— 見 §7
- **封鎖使用者** —— 見 §8
- **借用者可選的權限模式**（照 Claude Code 那個 manual / edit / auto 選單做）——
  那個控制項在 Claude Code 裡成立，是因為三個前提：動的是**你自己的**檔案、
  你**人在現場**、需要許可時它**跳出來問你**。這個系統三個都不成立：job 動的是
  複本（附件先進 MinIO，worker 下載到全新工作目錄，跑完整個目錄刪掉，你電腦上
  那份沒被碰過）、借用者可能已經關掉瀏覽器（§4「可以離開」是刻意的）、
  `--permission-prompts none` 也沒有人在線上回答提示。搬過來會變成裝飾。

  放寬的方向更不能做：那是拿**出租者的**機器冒險，而他不在場。降級（唯讀）則
  重複了 prompt 已經能做的事 —— 「只要給我建議，不要改檔案」用講的比開關細，
  還能逐檔講。而且唯讀要真的成立就得連 `Bash` 一起拿掉（有 shell 就能寫檔），
  那會連 pptx/xlsx/docx 都產不出來，因為那些 skill 是跑 Python 腳本的。
  **留 `Bash` 的唯讀是假的保護，比沒有更糟。**

  固定值見 SPEC.md §9：`--allowedTools "Read,Edit,Bash"`、`acceptEdits`、
  `--permission-prompts none`。它其實比 Claude Code 的 Auto **更緊** —— 工具只有
  三個，不在清單上的（`Write`、`WebFetch`）直接沒有，不是跳出來問。
- **登入頁放裝飾性內容**（星座運勢、每日一句、吉祥物之類的提案）—— 登入頁底下
  那句「密碼只會轉交給 Observ，claude-boba 不儲存它」是要被當真的，
  而 §9 說「正因為平常很鬆，嚴肅的地方才顯得嚴肅」。旁邊擺一則玩笑，那句話會
  一起被讀成裝飾。另外兩個理由：登入頁在**登入之前**，拿不到使用者身分，星座這類
  東西只能叫人多填一欄或隨機發，隨機的一看就知道是假的；而且人在這頁的目標是
  趕快進去。**玩心的預算花在排行榜（§7）與欠債通知，那裡玩才有人看得到。**

## 11. 待補（Phase 1 之後）

這些要等 job pipeline 真的跑過才知道真實樣貌：

- Job 列表的欄位與排序
- 各類錯誤的實際訊息字句
- Job 跑 8 分鐘時畫面的實際體感，以及是否需要中途提示
- 行動裝置版面（BD/PM 有可能在手機上看通知後點進來）

以下是明確的功能缺口，不是待觀察：

- **結清沒有通知**。債主按了「他還了」之後，借用者不會收到任何訊息 ——
  網頁帳本是他唯一的發現途徑。結清是**債主單方面宣告**的（SPEC.md §4.8），
  所以借用者不主動去看就不會知道自己被銷帳了。通知頁的文案已經先拿掉
  「結清時會通知你」這句，避免說謊。
