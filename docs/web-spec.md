# claude-boba Web 規格 v0.1

> 系統規格在 [../SPEC.md](../SPEC.md)。這份只講**使用者看到什麼**：畫面、狀態、文案。
> 兩份分開是刻意的 —— 混在一起會互相稀釋。

---

## 0. 這份文件的讀法

Web 是這個產品本身。後端只是讓它能跑。

TA 是 **BD / PM 與 RD 混合**（SPEC §1）。前者九成不寫程式、用 claude.ai 或 Claude app；
後者用 Claude Code。**兩種人的路徑都要是第一級公民**，不能有一邊是「進階功能」。

---

## 1. 技術選型

**React 19 + Vite + TypeScript**，前後端分離，Hub 提供 REST + SSE。

選它不是因為技術上最省，而是因為 `lighthouse-saas-api` 的 `observ-event-dashboard` 與
`easy_visionai_tools` 都是這一套 —— 團隊既有經驗直接適用，交接時不用多學一種東西。

**即時更新走 SSE，但必須有 poll fallback。** 連線中斷就退回每 5 秒 poll；
使用者不該察覺差別。SSE 的內容見 §4。

---

## 2. 畫面清單

六個，全做。第七個是試玩期的鷹架，會被拆掉。

| # | 畫面 | 給誰 | 重點 |
|---|---|---|---|
| 1 | **提交 job** | 借用者 | 登入後的首頁。單頁，不分步驟 |
| 2 | **我的 job** | 借用者 | 列表 + 狀態 |
| 3 | **Job 詳情** | 借用者 | 即時串流、輸出下載、花費 |
| 4 | **帳本** | 雙方 | 我欠誰 / 誰欠我，出租者在這裡結清 |
| 5 | **排行榜** | 全部 | 欠債王。產品靈魂 |
| 6 | **我來代跑** | 出租者 | 出借條件、出借帳號與用量、**緊急停止** |
| 7 | **許願板** | 全部 | 收試玩期回饋。**鷹架，有下架條件，見 §12** |

第 6 個最容易被漏掉，但出租者是供給側 —— **沒有他們就沒有服務**。

第 7 個跟前六個不同：它**預計要被刪掉**。不要把它當成長期功能來蓋，
也不要讓別的畫面依賴它。下架條件與理由全部寫在 §12。

## 3. 提交頁（首頁）

登入後直接落在這裡。使用情境是「我額度爆了，很急」，所以最短路徑優先；
帳本與排行榜放導覽列，想看的人自己去。

**單頁，由上而下：**

```
┌─ 對話內容 ─────────────────────────────┐
│ [ 大文字框：貼上你的對話 ]              │
│ 或 [ 上傳 .jsonl ]  ← Claude Code 使用者 │
└────────────────────────────────────────┘
  ⚠️ 貼上的對話會被「讀過」，但 Claude 不會真的記得當時的環境。
     用 Claude Code 的話，上傳 .jsonl 可以真正接續。

[ 附件（選填） ]

出租者： [ 自動（推薦） ▾ ]
Model：  [ Sonnet（預設） ▾ ]

☐ 我了解 Vivian 技術上可以看到我送出的內容

                              [ 送出 ]
```

### 上傳 `.jsonl`（已實作）

**分界是工具，不是職稱。** 不要寫成「RD 上傳、BD/PM 貼上」—— 剛好用過
Claude Code 的 PM 就有 `.jsonl`，照職稱寫會讓他以為這功能不關他的事。
畫面上要問的是「這個對話是在你電腦上用 Claude Code 跑的嗎」。

**不要在畫面上叫使用者判斷自己屬於哪一類。** 這段文案照職稱寫過、照 app 名稱
寫過、照「session 存在哪」寫過，三次都錯 —— 那需要使用者（和寫文案的人）懂產品
架構，而產品架構會變。

改成讓指令當測試：`ls -t ~/.claude/projects/*/*.jsonl | head -5`，有東西就上傳，
沒有就貼上。這行之所以夠用，是因為 **Cowork 的 local session 也寫在
`~/.claude/projects/`**，跟 CLI 同一棵樹（SPEC §11 spike #7 實測）。

| 來源 | 本機有 transcript？ |
|---|---|
| 終端機 `claude`、VS Code / JetBrains 擴充、Desktop 的 Code 分頁 | ✅ |
| Cowork **local** session | ✅ 同一棵樹。metadata 另放，靠 `cliSessionId` 對應 |
| Cowork **cloud** session | ❌ 跑在 Anthropic 伺服器，session 存帳號 |
| Chat、claude.ai、手機 | ❌ |

**而「沒有 transcript」不是少了一個功能。** 那些對話跑在伺服器上，不存在可以餵進
`--resume` 的匯出格式；就算生得出一個檔案，裝的資訊也跟貼上一模一樣。

而**對 BD/PM 來說，貼上損失的東西遠比對 RD 少**：`--resume` 比貼上多帶的是
工具呼叫的結果與本機檔案狀態，而 claude.ai 的對話本來就沒有這些。他們真正
帶不過來的只有**附件**（見〈不做／還沒做〉）。

也不要想「幫他們合成一份」：`--resume` 比貼上多帶的不是檔案格式，是工具呼叫的
結果與檔案狀態。聊天對話裡沒有這些，所以合成出來的 transcript 裝的資訊跟貼上
一模一樣 —— 花工程換零收益。

還有一件事讓這個落差只存在於**第一跳**：job 跑完 worker 會把自己的 transcript
存起來，所以第二輪之後用「接著問」，不論來源都是真的續跑。

因此提交頁的說明要分兩種來源講，而且**指示要給到能貼進終端機的程度**。
「去 `~/.claude/projects/` 找」不是可執行的指示 —— 那底下一個專案一個資料夾，
隨便一台開發機就上百個 session 檔，檔名還是看不出內容的 session id。

檔案由瀏覽器直接 PUT 進 MinIO（`POST /api/uploads/transcript` 換一張預簽票），
不經過 Hub。Hub 在建立 job 時才驗：**key 的 prefix 必須是呼叫者自己的**、
存在、≤ 50 MB、開頭幾行是 JSON。第一項是存取控制 —— 不驗的話任何人都能把
`transcript_key` 指到別人 job 的 transcript。

**帶了檔案之後，文字框的意思會變。** 上下文在檔案裡，那個框要填的是
「接下來做什麼」，標題與提示都跟著換：

| | 沒有檔案 | 有檔案 |
|---|---|---|
| 標題 | 對話內容 | 接下來要它做什麼 |
| 提示 | ⚠️ 貼上的對話會被「讀過」，但 Claude 不會真的記得當時的環境 | ✅ 這是真的續跑，出租者那邊用 `--resume` 接上 |

**檔案一選好就上傳，不是等按下送出。** 50 MB 的檔案在按下送出之後才開始傳，
使用者會盯著一顆沒反應的按鈕。大小與格式也是前端先擋一次 —— 不要讓人
上傳三分鐘才說太大。


### 出租者下拉

預設「自動（推薦）」，展開後列出線上 worker 及其差異：

```
├ 自動（推薦）
├ Vivian   🟢 線上 · 🔒 白名單網路 · 額度 🟢 充裕 · Sonnet/Haiku
└ Alex     🟢 線上 · 🌐 開放網路 · 額度 🟡 快滿了 · Sonnet/Haiku/Opus
```

三件事一次解決：§7 的「改送」有地方去、RD 知道該挑開放網路的、
而額度紅綠燈讓借用者對別人的餘裕有感 —— **這個訊號本身就是社交剎車**。

**額度只顯示紅綠燈，不顯示百分比。** 精確數字會讓人盤算「他還有 66%，再送一個沒差」，
把人情變成資源計算。模糊剛好：足夠傳達分寸，不足以精算。

> ⚠️ **2026-09-22：這顆燈的語意變了。** 一位出租者現在可以有多個**出借帳號**
> （SPEC §4.12），而燈只有一顆 —— 它取那個人底下**最充裕**的帳號。
> 所以它回答的問題從「他的帳號還剩多少」變成「**他的池子現在接不接得動**」，
> 而那正是借用者真正在問的事（派單也是挑 utilization 低的那個去跑）。
>
> 不取平均：個人帳號 10%、公司帳號 90% 平均出來的「🟡 快滿了」，
> 兩個帳號都不是那個狀態。
>
> **這條「不顯示百分比」只約束借用者看別人。** 出租者看自己的精確數字一直是
> 允許的（`_view()` 裡的 `if owner:`），見 §8。

### 指令（2026-09-22）

輸入列上那顆 `/` 已經在了（`web/src/Composer.tsx`、`CommandPicker.tsx`），
點開是分好組的中文動詞短句。**畫面上不會出現「skill」這個詞** —— 那要懂產品架構
才看得懂，而 §3 前面那段已經記取過三次同樣的教訓。

**問題不是描述不夠，是 `/` 不會被發現。** 知道 `/` 是什麼的人不需要被告知；
不知道的人（正是這個功能為他做的那個人）永遠不會點它。

**所以：文字框空著的時候，框內露出四個 chip，一打字就收掉。**

```
┌─ 對話內容 ─────────────────────────────┐
│                                         │
│  [做簡報] [做表格] [畫圖表] [這裡能做什麼] │
└────────────────────────────────────────┘
```

- **不預設展開整份清單**：五組十九項攤在一個「額度爆了、很急」的人面前，
  違反這一頁「最短路徑優先」。
- **不另開一塊常駐區**：會跟輸入列搶位置，而 CONTEXT.md 已經定死「輸入列裡只放動作」——
  兩個地方管同一件事就是下一個 bug。
- **不依角色切換**（RD 看到工程那組）：要求系統判斷誰是 RD，而這一頁已經錯過三次。
- **為什麼是這四個**：前三個是 BD/PM 用自己的 Claude app **做不到**的事（產不出檔案）。
  第四個 `這裡能做什麼` 排最後，它是逃生門 —— 點了它，`/` 這個手勢本身就被教會了。
- **露哪幾個由 hub 的 `commands.json` 標 `chip` 決定，不寫死在前端。**
  那是編輯判斷（要向 BD/PM 講什麼），會改，而改它不該要動前端。

**清單顯示的是聯集，但選了指令會收窄派單範圍**（SPEC §4.13）。
指令因此是〈出租者下拉〉那三項差異之外的**第四項** —— 不同代跑者會的不一樣。
選了沒人能跑的指令，要當場講（「目前線上沒有人能跑這個」），不能默默排隊。

### 缺服務憑證時（2026-09-22）

有些指令要連外部服務（第一個是 Observ），需要委託者自己的**服務憑證**（ADR-0002）。

**在他選了那個指令的當下、原地要，不做前置設定頁。** 要求使用者先逛設定頁才知道
自己缺什麼，正是這個功能要解決的那個失敗：「不會設 `.env`」的本質是
**得先去別的地方把東西配好才能開始**。原地問的好處是它帶著上下文 ——
他此刻知道自己為什麼需要它。

交一次就存著，之後同一個指令不再問。送出時 hub 會先驗一次，**驗不過就不收單** ——
不能讓貼錯的憑證燒掉代跑者的額度。驗不過的訊息要講清楚是憑證的問題，
不要讓人以為是指令壞了。

### Model 選單

顯示的是「站台白名單 ∩ 該出租者白名單」的交集（SPEC §9）。**預設 Sonnet**。

預設不是 Fable，因為 BD/PM 不會知道差別、會直接送出，而那等於每個 job 貴 5 倍。
想要更好的人自己會改。

**Fable（2026-09-23）只在有人開的時候才在下拉裡。** 沒人開就不列，下拉底下一行字
講「為什麼沒有」跟「該去找誰」，四種狀態分開講，因為使用者接下來該做的事不一樣：

| 狀態 | 文案 |
|---|---|
| 指定了某人，他沒開 | 「{name} 沒開 Fable。帶杯手搖去拜託他，或換回自動。」 |
| 自動，線上有人但都沒開 | 「線上沒人開 Fable。想跑的話，帶杯手搖去拜託 {A、B、C}。」 |
| 自動，有人開了但沒在接單 | 「{X} 有開 Fable，但現在沒在接單。」 |
| 全站沒任何人開過 | 「全站還沒有人開 Fable。」 |

點名最多三個，超過就寫「一位線上的代跑者」。「有開但沒在接單」要單獨講，因為那個人
的答案是等他，不是求他。語氣沿用 §9，但**不能讓人以為問了就會有**。

不做成 disabled option：原生 `<select>` 的 disabled option 掛不了說明，而「為什麼沒有」
才是重點。也不做「送出才被 Hub 擋」：讓人填完 prompt、上傳 50 MB 才被打回，不行。

選到 Fable 時多一行「Fable 一趟常常會超出級距表 —— 到那裡就不是請飲料的等級了」。
用級距表的詞、不出數字（SPEC §4.7：精確數字會讓人計較）。

### 隱私勾選

**必須主動勾選，不能預設打勾。** 預設打勾的同意等於沒有揭露，
會架空 SPEC §4.3 定下的誠實原則。

> ☐ 我了解 **<出租者> 技術上可以看到我送出的內容**
>
> 這個 job 會在對方的電腦上執行。系統預設不讓出租者查看內容，但技術上他有能力看到。
> 請不要送出公司機密、客戶個資，或任何你不希望被對方看到的東西。

### 上傳限制

單一 transcript **50 MB**、附件合計 **50 MB**、單一 job 上限 **100 MB**。**前端先擋**，
不要讓人上傳三分鐘才說太大。

依據：一句 `"pong"` 的 transcript 就 224 KB（系統提示與工具定義佔絕大部分），
真實 RD session 估 10–50 MB。超過 50 MB 的 session，`--resume` 本身也會慢到不實用。

另外：**單檔 50 MB、最多 20 個**（`hub/app/schemas.py`）。副檔名**不限** ——
擋副檔名沒有意義，能擋的是結構：附件平鋪在工作目錄根層（`worker/_place_attachments`），
所以「傳整個資料夾」本來就不成立。

### 帶 codebase 進來：zip（2026-09-22）

工程類指令（`/code-review`、`/tdd`、`/diagnosing-bugs`…）要有 code 才有意義，
而委託者的路徑是**把專案壓成一個 zip 傳上來**，Claude 在容器裡自己解
（image 有 `unzip`）。worker 不解 —— zip bomb 撐爆的是那個一次性容器，
而不用在 worker 裡再寫一份自己的安全解壓縮。

**zip 裡要含 `.git`，而且這不是可有可無的。** `/code-review`、`/security-review`、
`/simplify` 三個都是**看 diff** 的：沒有 `.git`，它們找不到基準點，多半也不會報錯，
會退而審整包然後照樣計一筆人情債。使用者用一杯飲料換到一份審錯對象的報告。
這句話寫在指令清單工程組的 hint 裡（`hub/app/data/commands.json`）。

**解開的那棵樹不算「產出的檔案」。** 不排除的話，那一區會被 50 個 repo 檔塞滿，
而 Claude 真正寫出來的東西被 `MAX_ARTIFACTS` 擠掉 —— 使用者拿回一堆自己傳進去的
東西，拿不到他要的那份。比對用 zip 自己的 (大小, CRC32) 而不是路徑，因為 `unzip`
可能解在根層也可能解進子目錄；**改過的照樣傳回去**，與既有附件那條規則一致。
`.git/` 則不必比對就排除。

帶 zip 的 job **timeout 從 10 分鐘放寬到 30 分鐘**（`worker.timeout_for_inputs`）。
理由不是成本 —— 成本封在 `--max-budget-usd`，那是代跑者自己填的上限，拉長 timeout
不會讓他多花錢。timeout 擋的是**不花 token 的卡死**（卡在 git、卡在無限迴圈的
Bash），那種 job 撞不到 budget，會一直佔著 `max_concurrency` 兩個執行位之一。
管理頁的「卡住的 job」門檻要跟著分流（`admin.running_stuck_seconds`），否則每個
健康的 code job 都會從第 12 分鐘列到第 30 分鐘。

### Context 提示（2026-09-22）

選了 session 檔之後，**只在它超過 140K token 時**才浮出一行字，講後果與唯一能做的
動作：「代跑時 Claude 會自動壓縮較早的內容，細節可能會掉 —— 重要的前提建議在下面
重講一次。」

- **數字是量到的，不是估的。** Claude Code 每一則 assistant row 都帶 `usage`，
  最後一則就是那一刻的 context 佔用。前端讀檔案結尾 512 KB 就有，不必 tokenize。
- **分母固定 200K。** `run-job.sh` 只帶 `--model`，沒有 1M context 的旗標，
  而站台白名單只有 sonnet / haiku。
- **讀出來的數字可能大於 200K，那不是 bug** —— 產生那份 session 的機器可以是 1M
  設定（實測四份真實檔案，兩份超過 200K，最大 563K）。那種對話不是「快滿了」是
  **一定裝不下**，所以文案分成兩種講法。
- **門檻是 70% 不是 90%**：你的 prompt、附件，以及 job 自己會跑出來的那幾十輪，
  都疊在這份 session 之上。剩下的 30% 是留給那一段的。
- **沒有 session 檔就沒有這行字。** 貼上的文字與附件沒有 token 數，只能用 byte
  粗估 —— 混一個精確值和一個爛估計在同一個提示裡，整個提示就都不可信了。
- **不做常駐的百分比量表。** 同 §3「額度只給紅綠燈不給百分比」那條線：精確數字會
  讓人盤算。八成的人送出的對話根本不到門檻，這行字對他們不該存在。

## 4. Job 詳情：等待與串流

### 心智模型：可以離開

Job 可能跑 10 分鐘。使用者**可以留在頁面看，也可以關掉分頁**，
跑完 Teams 會通知。明講這件事，等待感就消失了。

### 串流內容

worker 用 `--output-format stream-json`，事件經 Hub 轉發給瀏覽器。顯示到**工具名稱**這一層：

```
🟢 Vivian 接下了這個 job
   正在讀取 requirements.txt
   正在執行指令
   💭 思考中…                        ← 預設收合，可展開
   
   「我看了你的需求，建議分成三個階段…」
   
   ⏱ 已執行 3 分 12 秒
```

- **顯示工具名稱與檔名，不顯示指令全文。** 理由不是隱私（那是借用者自己的內容），
  是畫面會被洗版 —— 一個 bash 指令可能二十行。
- **thinking 預設收合。** 對 BD/PM 是噪音，對 RD 有用，收合可展開兩邊都照顧。
- **不要顯示進度條。** 我們沒有進度資料，進度條會撒謊 —— 走到 70% 會讓人以為快好了。
  顯示「已執行 3 分 12 秒」誠實得多，數字變大時使用者自己會決定要不要走。

### 離開後回來

**Hub 保存整份事件流。** 重新進入頁面時先重播歷史，再接上即時串流。

這也是 SSE 斷線重連的機制：重連時帶上「我看到第幾個事件」，Hub 從那裡續傳。
成本不高 —— 事件流本來就要存進 MinIO 當明細（SPEC §7）。

### 帶回自己的機器續跑（2026-09-22）

「接著問」底下多一顆「下載這份對話（.jsonl）」，以及收合起來的放檔指令。

**放在「接著問」同一區，不是「產出的檔案」那一區。** 那一區的定義是「**新**檔案與
被改過的附件」，transcript 兩者都不是 —— 混進去會讓那句說明變成假的。而它跟接著問
是同一件事的兩條路：在站上續、回自己機器上用自己的額度續。

- **開放條件與 `can_follow_up` 完全一致**（成功 + 真的留下 transcript）。兩顆按鈕
  並排，條件不一致的話其中一顆會是死的。
- **只有委託者本人下載得到。** 這比 `_get_job` 的規則更緊：出租者跑了這個 job、
  讀得到它的內容，但下載是把整份對話搬出站台，而 30 天 lifecycle 是隱私承諾的
  一部分（SPEC §8）。搬得走的只有那份對話的主人 —— 對他本身不構成新的外洩。
- **預簽 URL 按了才開。** 它本身就是憑證，沒有人要下載時不該先開一張出來。
- **檔名是 job id + `.jsonl`。** Claude Code 是用檔名認 session 的，改了名就
  `--resume` 不到。

## 5. 失敗的呈現

三類，揭露程度不同。**不論哪一類都不計債**（SPEC §5）。

| 類型 | 例子 | 給使用者看什麼 |
|---|---|---|
| **可修復** | 檔太大、白名單擋到、逾時、超出預算上限 | 完整原因 + 明確下一步 |
| **系統問題** | worker 掛了、MinIO 寫入失敗、Observ token 過期 | 「系統問題，已記錄」+ job id |
| **Claude 本身** | API 錯誤、模型拒答、rate limit | 原始訊息（那是 Claude 給使用者的，不是我們的） |

### 分類做在後端，前端只負責渲染

判斷寫在 `hub/app/failures.py`，job 詳情的 API 會回一個 `failure` 物件：

```json
{
  "kind": "fixable | system | claude",
  "title": "超過時間上限，已中止",
  "hint": "把要做的事拆小一點再送一次。這次不計債。",
  "show_detail": true,
  "blocked_by_network": false
}
```

前端的責任只有三件：顯示 `title`、顯示 `hint`（若有）、以及**只在
`show_detail` 為真時**才顯示 `error_detail`。系統問題的 stderr 對使用者
沒有意義，也幫不上忙。

放後端的理由：同一份判斷未來 Teams 通知也要用，而且前端會改版 ——
把規則放在會被重寫的地方等於會遺失。

### 白名單擋到要特別處理

這會是 RD 最常撞的牆。若只寫「執行失敗」，他們會以為工具壞了。
後端已經會認出這種情況並回 `blocked_by_network: true`。

> ⚠️ 這個 job 嘗試連線到 `pypi.org`，但 Vivian 的 worker 是白名單網路模式。
>
> 〔改送給 Alex（開放網路）〕

**那個按鈕是重點**，不是那句話。

> 🚧 按鈕還沒實作 —— 目前只有一台 worker，按了沒地方送。
> 有第二台之後再做，後端的 `blocked_by_network` 已經備好。

### 結清由債主按

出租者在帳本頁每一筆旁邊按「他還了」即結清（SPEC §4.8）。
**Teams 通知裡也要能直接按** —— 債主通常懶得特地開網頁。

借用者這邊有「我請過了，戳他確認」，把催促責任放在欠債的人身上。

### 債務不設到期日，但顯示欠了幾天

比自動勾銷更有社交壓力，也更好笑。

## 7. 排行榜

**欠債王 = 未結清筆數最多的人**，同時顯示累計金額。**時間範圍是全部，不按月重置。**

為什麼不用累計金額排：一個跑了一次大 job、當天就請客的人會高居榜首 —— 那是在懲罰使用者。
用未結清筆數的話，榜首是那個欠了五杯飲料三個禮拜的人，**那才是大家想調侃的對象**。

不重置是因為這個系統的核心資產就是「債會一直記著」。

只顯示聚合數字，**不做動態牆** —— 「誰跟誰借了什麼」本身就是資訊，會踩到 SPEC §4.3 的隱私線。

## 8. 我來代跑（出租者）

極簡：一張狀態卡 + 設定 + 停止鈕。

```
┌──────────────────────────────────┐
│ 🟢 線上 · 最後回報 12 秒前        │
│ 五小時窗口 🟢 充裕                │
│ 今天跑了 3 個 job · 借出 $4.20    │
│                                  │
│ 執行中：job #a3f2（BD Kevin）     │
│         已執行 2 分 08 秒         │
│         〔停止〕                  │
│                                  │
│ 〔暫停接單〕                      │
└──────────────────────────────────┘
```

設定：單次預算上限、網路模式、可用 model。**並行數不在這裡** ——
它是每個出借帳號的物理性質，不是使用者在表達意願的旋鈕（SPEC §4.12）。

### 出借帳號與額度面板（2026-09-22）

SPEC §4.12 之後這頁要列出**出借帳號**。一個帳號的時候也列 —— 那一列不是為了
多帳號而存在，它是放用量的地方：

```
你的出借帳號
┌──────────────────────────────────────────────┐
│ 個人 Max                                     │
│ 五小時窗  ▓▓▓░░░░░░░  34%   1 小時後重置      │
│ 七天窗    ▓▓▓░░░░░░░  30%   2 天後重置        │
│ 資料為 3 分鐘前                               │
├──────────────────────────────────────────────┤
│ 公司帳號（批准者：<填的那句話>）   ⚠️ 需重新授權 │
│ 這個帳號目前不接單，其他帳號照常                │
└──────────────────────────────────────────────┘
〔再授權一個帳號〕
```

**百分比與重置倒數只給本人，不給借用者。** 理由跟 §3 那條完全一樣：
知道「他一小時後就滿血」會直接變成「那我現在多送幾個」。

**過期的數字不顯示成即時的。** 標「資料為 X 前」，太舊就顯示「不知道」——
出租者自己在別的地方也在燒同一個帳號，站台不會知道，這時掛一個理直氣壯的
34% 比不顯示更糟。資料怎麼來、多久問一次，見 SPEC §11 spike #10。

**其中一個帳號的 token 失效時，只有那個帳號停止接單，其他照跑。**
job 不受影響（另一個帳號會接）。這是「出借帳號」這個概念在整個 UI 裡
唯一露臉的地方 —— 借用者那側從頭到尾看不到它。

**再授權一次已經有 token 的帳號會換掉它 —— 而且是按下去的當下就換。**

> ⚠️ **2026-09-22 訂正。** 這一段原本寫「舊的那組站台不會再用，但它在 Claude
> 那邊仍然有效到期滿」。**那是錯的。** hub 一按下去就在跑 `claude setup-token`
> （`hub/app/authorize.py`），而它會當場作廢同一個帳號的舊 token，不是等授權碼
> 貼回來才換。
>
> 當天實際發生：按了、沒貼碼、離開 → 下一個 job 401。而失敗被分類成「超出預算，
> 換 Haiku 再試一次」，把人導去一條完全錯的路（見 `hub/app/failures.py`）。
>
> 錯的方向特別糟 —— 它讓人以為中途放棄沒有代價。

所以按鈕旁邊要講的是：**按下去就作廢舊的，中途放棄這個帳號會變成不能用。**
不擋（換帳號、token 被撤銷後重授權都是正常需求），但不能無聲。

**授權失效之後，那個帳號要自己停下來。** 失效是沉默的：token 死了之後站台仍然
認為它可用、仍然派 job 給它，每一個都用一模一樣的方式失敗，而畫面上它還是綠的。
所以 job 回報認證失敗時，hub 把那個帳號標成需重新授權、停止派單，並通知它的主人
（只停那一個帳號，其他照跑）。

### 停止的範圍

**停當前 job + 可暫停接單。不做「封鎖特定借用者」。**

封鎖在人情系統裡是社交核彈 —— 一旦按鈕存在，沒按也會有人猜想。
而它要解決的問題（某人一直濫用）在 10 人團隊裡，用講的比用系統快得多。

### 停止的後端已完成，UI 待接

`POST /api/jobs/{id}/stop`，body `{ "note": "..." }`（note 選填）。
job 詳情的 `can_stop` 欄位告訴前端現在這個人能不能按 —— 只有**正在跑這個
job 的出租者**能停，而且它必須還在執行中。

Hub 會立刻把狀態改成 `cancelled`，不等 worker 確認 —— 否則按了之後畫面
沒反應。真正殺掉容器的是 worker，它在下一次回報時從回應裡收到 cancel。

> 📌 worker 每 3 秒會空跑一次回報，即使 job 沒有任何輸出。沒有這個心跳，
> 停止只在 job 還在吐事件時才有效 —— 而最需要停止的正是安靜卡住的那種。

### 停止時可選填一句話

這個欄位的價值高於整個停止功能：

> ❌ 「你的 job 已被出租者終止。」
> ✅ 「Vivian 終止了你的 job：『這個看起來會跑很久，我等下要開會，晚點再幫你跑』」

**沒有那句話，停止會被讀成拒絕。**

## 9. 語氣

**平常玩笑感，四個地方切換成完全正經：**

1. **隱私警告** —— 用可愛的語氣講「他看得到你的內容」，人會不當一回事
2. **錯誤訊息** —— 使用者要的是「發生什麼事、我該怎麼辦」，不是俏皮話
3. **金額** —— 顯示 US$3.20 就顯示 US$3.20，不要模糊化
4. **許願板貼圖前那句提示**（2026-09-22 加）—— 許願板是全站語氣最鬆的一塊，
   而它剛好是唯一會公開顯示使用者上傳圖片的地方。那句話要放在**上傳按鈕旁邊**，
   不是頁面頂端的說明區。理由見 ADR-0005

其餘全部可以玩。**這個對比本身就是設計**：正因為平常很鬆，嚴肅的地方才顯得嚴肅。
如果整個介面都在搞笑，隱私警告就會被當成裝飾。

### 金額的位數，與唯一一個台幣（2026-09-22）

「不要模糊化」要的是**不含糊**，不是把浮點數的尾巴全印出來。後端存的是
`Numeric(12,6)`，照字串印會是 `US$0.183921` —— 後面四位沒有人做得了任何決定。
四個顯示金額的地方一律取到小數點後兩位，格式化只有 `web/src/money.ts` 一份。

**但不可以印出 `US$0.00`。** SPEC §11 量到一個小任務大約是「一杯飲料的 1/100」，
取兩位之後它們會全部變成 0.00，而「花費 US$0.00」讀起來是「這次沒花到錢」。
低於半分錢的印 `< US$0.01`：有花錢、少到看不出來，兩件事都是真的。

**台幣只出現在管理頁的「累計花費」，而且是附註。** 讀者是站台管理者，他要的是
量級感；帳單是美金，對帳一律以美金為準，所以美金在前、台幣加「約」。
其餘所有金額不換算 —— §4.7 的級距表才是給使用者的那層翻譯，而它刻意是粗的，
旁邊擺一把細尺就會有人開始比價。

匯率是**即時去查的**，不是寫死的係數（`hub/app/fxrate.py`）。查不到就顯示美金
並寫出原因，不退化成一個猜的數字 —— 管理頁不放假的綠燈，金額也一樣。
臺灣銀行官網對非瀏覽器一律回 bot challenge，所以走 FinMind 的台銀牌價鏡像，
畫面上那句話因此寫「（經 FinMind）」。

### 欠債通知（Teams）

> 🧋 你欠 Vivian 一杯手搖
> 剛才那個 job 花了 US$2.30（Sonnet 5，約 1.2M tokens）。
> 已經欠 3 天了。〔我請過了〕

## 10. 不做的事

- **儀表板首頁** —— 為每天會用的工具設計的，而這個工具最好的狀態是「大家很少需要用到」
- **互動式出租者引導** —— 工程量遠大於價值。出租者只有幾個人、都是 RD，
  一頁寫清楚的安裝文件加一個 `install.sh` 就夠
- **獨立的新手說明頁** —— 沒人會讀。說明要長在提交頁本身（§3 的那些文案就是在做這件事）
- **動態牆** —— 見 §7。**許願板（§12）不是它的變體，不要把這條當成先例推翻掉**：
  動態牆洩漏的是「誰跟誰借了什麼」，那是系統代替當事人講出來的；許願板上只有
  當事人自己選擇打進去的字，而且貼之前看得到「這會被所有人看到」。
  兩者的差別不在公不公開，在**內容是誰決定要公開的**
- **封鎖使用者** —— 見 §8
- **借用者可選的權限模式**（照 Claude Code 那個 manual / edit / auto 選單做）——
  那個控制項在 Claude Code 裡成立，是因為三個前提：動的是**你自己的**檔案、
  你**人在現場**、需要許可時它**跳出來問你**。這個系統三個都不成立：job 動的是
  複本（附件先進 MinIO，worker 下載到全新工作目錄，跑完整個目錄刪掉，你電腦上
  那份沒被碰過）、借用者可能已經關掉瀏覽器（§4「可以離開」是刻意的）、
  `--permission-prompts none` 也沒有人在線上回答提示。搬過來會變成裝飾。

  放寬的方向更不能做：那是拿**出租者的**機器冒險，而他不在場。降級（唯讀）則
  重複了 prompt 已經能做的事 —— 「只要給我建議，不要改檔案」用講的比開關細，
  還能逐檔講。而且唯讀要真的成立就得連 `Bash` 一起拿掉（有 shell 就能寫檔），
  那會連 pptx/xlsx/docx 都產不出來，因為那些 skill 是跑 Python 腳本的。
  **留 `Bash` 的唯讀是假的保護，比沒有更糟。**

  固定值見 SPEC.md §9：`--allowedTools "Read,Edit,Bash"`、`acceptEdits`、
  `--permission-prompts none`。它其實比 Claude Code 的 Auto **更緊** —— 工具只有
  三個，不在清單上的（`Write`、`WebFetch`）直接沒有，不是跳出來問。
- **登入頁放裝飾性內容**（星座運勢、每日一句、吉祥物之類的提案）—— 登入頁底下
  那句「密碼只會轉交給 Observ，claude-boba 不儲存它」是要被當真的，
  而 §9 說「正因為平常很鬆，嚴肅的地方才顯得嚴肅」。旁邊擺一則玩笑，那句話會
  一起被讀成裝飾。另外兩個理由：登入頁在**登入之前**，拿不到使用者身分，星座這類
  東西只能叫人多填一欄或隨機發，隨機的一看就知道是假的；而且人在這頁的目標是
  趕快進去。**玩心的預算花在排行榜（§7）與欠債通知，那裡玩才有人看得到。**

## 12. 許願板（2026-09-22，試玩期鷹架）

**這個產品現在只是試玩，而試玩期缺的是回饋，不是需求，也不是供給。**
許願板是拿來補那一項的：一面收「這個產品哪裡不好用、我還想要什麼」的牆。

三件它**刻意不是**的事，先講，因為每一件都有人會想順手加回來：

| 看起來像 | 其實是 |
|---|---|
| 讓人許願、別人接單去做 | **不是**。牆上沒有「處理中」，系統不記錄任何人打算做什麼 |
| §7 否決掉的動態牆 | **不是**。差別不在公不公開，在內容是誰決定要公開的 —— 見 §10 |
| 第七個長期畫面 | **不是**。它有下架條件，預計會被整組刪掉 |

### 下架條件

**Phase 2 用真實帳號完整驗過，或連續 30 天沒有新的一則 —— 先到者為準，移除整面牆。**

這條現在就寫死，是因為「反正也沒壞」會讓它一直留著，而**一面三個月沒人貼的死牆比
沒有牆更傷** —— 它會告訴每個進來的人「這裡沒人」。

牆死掉的時候要有人負責拆。拆的範圍：四張表（SPEC §6）、MinIO 的 `wishes/` prefix
（SPEC §8）、導覽列那一項、job 詳情頁那個入口，以及 **`emoji-picker-react` 這個相依
（ADR-0004，拆之前先確認沒有別處在用）**。

### 一則願望

**分類（四選一）＋ 內文 ＋ 署名。**

| 分類 | 什麼時候選它 |
|---|---|
| 壞掉了 | 它應該要動但沒動 |
| 想要一個指令 | 我想要它會做某件事 |
| 體驗不好 | 它動了，但很難用 |
| 其他 | 上面三個都不像 |

**「想要一個指令」值得獨立一類**，因為它是唯一接得到既有機制的 —— 它直通 SPEC §4.13
的 `commands.json`，落地路徑是現成的。

**署名是強制的，沒有匿名。** 兩個理由：五到十個人的團隊裡**匿名是假的**（用詞、
抱怨的是哪個 job，一看就知道是誰），而假匿名比署名更糟，它讓人以為自己安全然後
講了以為不會被認出來的話；另一個理由更實際 —— 收到「串流卡住」時唯一有用的下一步
是**去問他那是哪個 job**，匿名把這條路砍了，而那正是這面牆存在的目的。

**「壞掉了」和「體驗不好」的界線是模糊的，我們知道。** 這是選四類而不是三類的
已知代價（串流卡住算哪一個？）。補償是**可以編輯**，見下。

### 不自動帶入任何 job 資訊

入口在 job 詳情頁結尾（見下），這個位置會非常自然地誘導出一個「順手帶上 job id ／
引用剛才那段錯誤訊息」的設計。**不要做。**

- 沒有 job id，資料表裡也不存（SPEC §6：許願板四張表跟 `jobs` 沒有任何外鍵）
- 不引用 prompt、不引用錯誤訊息 —— 錯誤訊息裡有路徑、檔名、prompt 片段
- 不做「只有維護者看得到的隱藏欄位」。那讓這面牆變成有隱藏通道的東西，
  而 SPEC §4.3 的整套論述建立在沒有隱藏通道上

要知道是哪個 job，就去問他。**這就是為什麼署名是強制的。**

### 貼圖

願望與留言都能貼。**四個分類一律開放**，不限「壞掉了」那一類。

- 單張 **5 MB**、一則最多 **3 張**、只收 `png` / `jpeg` / `webp`
- **不收 `svg`** —— 它可以帶 script，而這是一面會渲染別人上傳內容的公開頁面。
  這是安全限制，不是效能限制
- **前端先擋**（沿用 §3 的原則）
- §3 那組 50 MB / 100 MB 是為 `.jsonl` transcript 訂的，**對截圖沒有意義，不要沿用**
- 上傳按鈕旁邊一句正經語氣的提示（§9 第 4 項）

**這一條弱化了 SPEC §4.3，是知情的取捨，完整論述在 ADR-0005 ——
想收回或想放寬之前先讀它。**

儲存與讀取見 SPEC §8：存 `wishes/{user_id}/`、**排除在 30 天 lifecycle 之外**、
不給 presigned URL，走 hub 一個要登入的端點。

### 留言

**單層，沒有回覆的回覆。** 巢狀在五到十人的牆上永遠用不到，但會讓版面、資料模型、
通知三處都變複雜。

留言最有價值的用法是「你說的是不是長這樣？」的來回，所以它跟願望一樣能貼圖 ——
不對稱的話人會改用「我再開一則新願望」來繞過，那更糟。

**一定會有人在留言裡寫「我來做」。這沒問題，而且是對的**：人講的話是人講的話，
系統狀態是系統狀態。牆上不會因此多出一個掛了十九天的標籤。

### 反應（emoji）

**任何 emoji 都能按**，用 `emoji-picker-react`（釘版本、`React.lazy` 載入，ADR-0004）。
願望與留言都能按。

- 一個人可以按多顆不同的，**同一顆再點一次是取消**（Teams / Slack 的既有語彙）
- **只顯示數字，不顯示是誰按的。** 五到十人的團隊裡「他對我的願望按了 👍，
  對別人的按了 🎉」是真的會被注意到的。這也跟 §7「只顯示聚合數字」同一條線 ——
  **留言已經是那條線上讓步最多的一步，反應這裡不再讓**
- **所有 emoji 等值。** 😭 是「我也遇到」還是「這很慘」？系統不該替它決定分數
- 不設顯示上限。五到十人的規模排不爆，真的爆了再說
- **膚色選擇器關掉**（`skinTonesDisabled`）。它在畫面上是一塊跟色系無關的黃方塊，
  但那只是表面理由 —— 真正的理由是**它會把同一顆 emoji 拆成好幾筆反應**：
  👍 和 👍🏽 是不同的字串，各自算一格。牆上只顯示數字，而五到十人的規模下，
  三個人按了「同一顆」卻顯示成三個 1，那個數字就失去意義了
- **picker 要吃我們的亮暗設定。** 它有自己的一套主題，不給就不會跟著 `data-theme`
  走 —— 暗色模式下會是一塊白的

### 實現了

**沒有「處理中」、沒有「認領中」。** 牆上只記錄已經發生的事。

在一個沒有人被指派任何事的 side project 裡，「認領中」這個狀態**記錄的多半是謊言** ——
認領完沒做的會比做了的多，而一面掛著三則「認領中（19 天前）」的牆比沒有認領功能
更打擊人。這跟 SPEC §4.8「結清由債主單方面宣告」是同一種誠實：
**系統只承認已完成的動作，不承認承諾。**

- **任何人都能標**，也能取消。不做權限模型 —— 鷹架，五到十人，加權限的成本高於
  被亂標的成本
- **PR 或 commit 連結必填**，沒有連結就標不了。這不是資料潔癖：
  沒有連結，「實現了」就退化成空頭宣告，跟被砍掉的「認領中」變回同一種東西
- 標了之後那則**留在牆上，樣式變掉、沉到底部**，不收進第二個分頁、不消失。
  已實現的願望是這面牆**唯一的活著證據**，把好消息藏起來等於放棄反駁「貼了也不會怎樣」

### 可以編輯

**可以編輯自己的願望與留言（含分類），不留編輯歷史、不顯示「已編輯」標記。**

這不是可有可無的：四個分類的界線模糊，**選錯一定會發生**。不能編輯的話唯一的修正
方式是刪掉重貼，而重貼會丟掉已經累積的反應和留言。

**但編輯不動貼圖。** 這條是實作時撞出來的：初版的編輯收了 `image_keys` 卻只寫回
分類與內文，結果是**改一個錯字就把截圖弄丟** —— 那正好廢掉「可以編輯」存在的理由。
要換圖就刪掉重貼，而那個代價要明講，不能悄悄發生。前端的編輯表單因此沒有貼圖欄位。

刪除：**只能刪自己的**。鷹架不需要審計軌跡；在一個全部署名的牆上，偷改內容的
社交成本本來就夠高了。

### 排序與篩選

**預設依最新排**，分類可篩。

不依熱門排，是因為痛點是回饋量不足 —— 依熱門排會讓剛貼的那則一出生就在第五名，
而那則正是最需要被看到的。

### 入口

**兩個，都要有：**

1. **job 詳情頁結尾，而且只在 job 跑完之後出現** —— 痛感發生的那一秒，人還在現場。
   §10 拒絕「獨立的新手說明頁」的理由（沒人會主動點進去）直接適用於這面牆，
   這個入口是它不變成死牆的關鍵。跑到一半不顯示，是因為那時還沒有東西可以回報，
   而一個永遠在那裡的入口會被眼睛自動略過
2. **導覽列一項** —— 1 只服務剛跑完 job 的人，而代跑者可能好幾天不跑 job，
   新願望廣播點進來也要有落點

### 通知

| 事件 | 送到哪 | 內容 |
|---|---|---|
| 有人貼了新願望 | **共用頻道廣播**（直接用 `TEAMS_CHANNEL_WEBHOOK`） | 一行＋連結，**不含內容** |
| 有人留言 | 貼文者的**通知目的地** | 「你的願望有人回了」＋連結，**不含內容** |
| 被標「實現了」 | 貼文者的**通知目的地** | 「你的願望實現了」＋連結，**不含內容** |

三件事要講清楚：

- **新願望那則不是通知目的地。** 通知目的地的定義是「**一個人**的通知會送到哪裡，
  每人恰好一個」（CONTEXT.md），而這則廣播沒有特定當事人。硬塞進那套模型會把
  「每人恰好一個」這條性質弄壞
- **留言不上頻道廣播。** 廣播的用途是「這裡有新東西」；一則熱門願望的十條留言會把
  共用頻道洗掉，然後下次真的有新願望時沒有人會看
- **全部不含內容。** 頻道通知定義上會送到共用頻道，而留言裡遲早會出現有人手打進去的
  job 細節。CONTEXT.md 已經立過「頻道通知不含金額」的先例 ——
  **公開目的地一律降級內容，不開特例**

**「實現了」那則通知是刻意補上的。** §11 已經記下一個同構的缺口：
「結清沒有通知，債主按了之後借用者不會收到任何訊息」，成因一模一樣（單方面宣告、
對方不看就不知道）。**在一份已經寫下這個缺陷的文件裡，新做的東西不該再犯一次。**

### 開站的第一則

**新牆的第一個訪客一定會看到零則，而他從那一刻學到的是「這裡沒人」。**

所以兩件事都做：

1. **空狀態文案**（可以玩，§9 說這面牆平常全部可以玩）
2. **維護者先用自己的帳號、署自己的名，貼三則真實的缺口。**
   不開匿名特例、不做假帳號。現成的材料就在文件裡：
   - 「結清沒有通知，債主按了之後對方不會知道」（§11）
   - 「代跑者交出 token 那一步的揭露文案還沒寫」（README 待辦 1）
   - 「隱私勾選點名了一個其實看不到內容的人」（README 待辦 2）

先貼真實的缺口有兩個作用：訪客看到「這裡有人在用」，以及他看到
**什麼樣的顆粒度算是一則好願望** —— 這比任何 placeholder 文案有效。
