# 誰在動什麼

這個 repo 同時有多個 Claude session 在寫。這份檔案的用途有三個：

1. **認領**：現在誰在動哪些檔案
2. **交接**：一邊做好、另一邊要接的契約
3. **已定案**：哪些事吵完了、哪些前提變了 —— 不要重新發明，也不要照舊前提寫

**還是不要在這裡抄逐筆的「我改了什麼」** —— `git log` 已經完整記錄了，手抄一份
只會過期，而過期的紀錄比沒有紀錄危險：

```bash
git log --format='%h %s' --name-only -15
```

第 3 項不重複 git log：它說得出「改了什麼」，說不出「**這件事已經吵完，別再動它**」。
所以那兩節只記結論與理由，每條掛 hash，對不上時**以 commit 為準**。

---

## 🚨 最重要的一條規則：不要用 `git add -A`

從 repo 根目錄 `git add -A` 會把**另一個 session 還沒提交的修改一起掃進你的
commit**。這不是假設 —— 2026-09-21 實際發生過：`6d978c6` 表面上是「出租者可以
中止 job」，實際卻夾帶了 UI 改版的 `App.tsx`、`index.css`、`MyWorker.tsx`、
`Notifications.tsx`。東西沒丟，但 commit 訊息與內容不符，歷史被弄糊。

**`git add <路徑>` 也不夠。** index 是共用的：另一個 session 只要先 `git add`
過，他的檔案就已經躺在 index 裡，你再 `git add` 自己的兩個檔案，commit 時會把
他的一起帶走。2026-09-22 實際發生：一個只該有 `SPEC.md` 與 `docs/web-spec.md`
的 commit，夾帶了另一個 session 的 `CONTEXT.md`、`hub/app/config.py`、
`hub/app/routers/auth.py`、`web/src/api.ts`、`Notifications.tsx`。

**用 commit 的 pathspec，它完全不看 index：**

```bash
git commit -F msg.txt -- web/src/pages/Submit.tsx web/src/index.css   # ✅
git add web/ && git commit                                            # ⚠️ 會帶走別人已 stage 的
git add -A                                                            # ❌ 永遠不要
```

`git commit -- <路徑>` 只從工作區取那幾個路徑，別人 stage 了什麼都不影響。
真的要先 `git add` 的話，**`git commit` 前一定要看 `git diff --cached --name-only`**，
出現不是你的檔案就停下來。

**`0e2f900` 現在就卡在這個狀態**：它的訊息只講 spike #7，實際還夾帶了另一個
session 的通知頁與 hub 設定。東西沒丟、能跑，但 `git log` 讀不出通知頁那些改動
是為什麼做的。要不要拆成兩筆**還沒決定** —— 拆要改寫歷史，所以得等兩邊都停手、
由使用者決定。在那之前不要有人去動它。

## 🚨 第二條規則：輸出要真的被執行過一次

這個 repo 抓到的問題**幾乎都是同一類**：東西看起來合理，但沒有人實際跑過、
渲染過、或查證過。列出來才看得出它是一個模式，不是一串巧合：

| 出了什麼事 | 看起來 | 實際 | 被誰抓到 |
|---|---|---|---|
| `.hint` 的負 margin | 貼齊欄位 | 接在按鈕後直接疊上去 | 使用者截圖 |
| 「🔕 尚未設定」 | 沒設就不會通知 | 早就在頻道被 `@` 了 | 讀 `notify.py` |
| 「結清時會通知你」 | 有這個通知 | 根本沒實作 | 追 `ledger.py` |
| `.findfile` 撐爆卡片 | `overflow-x` 擋得住 | flex 項目不肯縮，外層先爆 | 使用者截圖 |
| `Application\ Support` | shell 跳脫 | **JS** 跳脫，渲染出來就沒了 | lint 的低階警告 |
| Cowork 被判到錯邊 | 它跑在雲端所以沒有本機檔 | local session 就在 `~/.claude/projects/` | 使用者去查才翻出來 |

共同點不是粗心，是**沒有跨過「從我的腦袋到真實環境」那一步**。每一條都只要
執行一次就會當場現形。

所以動這三類東西時，交出去之前先做對應的那件事：

- **要被複製貼上的指令** —— 真的貼進 shell 跑一次。不是 `bash -n`，是真的跑，
  看它的錯誤訊息是不是你預期的那一種。如果它寫在 JSX 的字串常值裡，**先求值**：
  JS 會先吃掉一層跳脫，你看到的原始碼不是使用者看到的東西。
- **版面** —— 在目標寬度真的渲染一次（手機是 390px）。CSS 屬性讀起來對，
  不代表它在那個容器裡成立 —— flex 與 grid 項目的 `min-width: auto` 是最常見的反例。

  ⚠️ **CSS 的特異性與載入順序用量的，不要用推的。** 2026-09-22：兩個人先後推論
  `.stop-panel .hint` 與 `.hint.under-field` 誰贏，**兩個都推錯，而且錯的方向相反**。
  量法：打包一次，`grep -ob` 看兩條規則在 bundle 裡的位元組位置（同特異性時後者贏），
  再用無頭瀏覽器對一個只含目標結構的頁面讀 `getComputedStyle`。實際結果是
  opt-in 一直正常（掛了 class 的贏），不存在的是 **opt-out** —— 面板裡任何裸 `.hint`
  都被強制吃到負上緣。這個差別直接改變修法：負上緣是多餘的，只有下緣該留。

  ⚠️ **驗證用的東西必須來自真實產物，不能是為了驗證而重寫的複製品。**
  2026-09-22：提交頁一次出現**兩個對話框**（加了新的輸入列、忘了刪舊的），
  而三張截圖（860 / 390 / 深色）加溢出檢查**全部回報正常**。原因是那些截圖
  渲染的是一份手寫的 HTML harness —— 而 harness 是照「我以為的結構」寫的，
  殘留那個區塊從一開始就不在裡面。**手寫的 harness 會忠實複製你腦中的錯誤，
  不會揭露它。**

  靜態 harness 對「這些 class 長什麼樣」有用，對「這一頁實際長什麼樣」無效。

  要看整頁就得用真實產物。**登入牆不是藉口** —— 用 Playwright 攔截 API 就能渲染
  真正的元件樹（2026-09-22 實測可用）：

  ```js
  await p.addInitScript(() => { try { localStorage.setItem('boba.token','x'); } catch {} });
  // ⚠️ catch-all 要註冊在**最前面**：Playwright 是後註冊的 route 先比對，
  //    反過來寫的話 '**/api/**' 會蓋掉 '**/api/auth/me'，display_name 變
  //    undefined、導覽列的名字渲染成空的 —— 而你多半不會發現，只會量到
  //    一個偏小的寬度。（2026-09-22 實際踩過，害一次 header 的寬度量錯。）
  await p.route('**/api/**', r => r.fulfill({ json: [] }));
  await p.route('**/api/auth/me', r => r.fulfill({ json: {
    id:'1', email:'v@x.com', display_name:'vivianfan',
    has_teams_webhook:false, channel_notifications:true, channel_name:'X' }}));
  await p.goto('http://localhost:5173/');
  ```

  **驗收自己的攔截**：先確認畫面上真的出現了你餵進去的值（例如導覽列的
  `vivianfan`）。攔截被遮蔽時頁面照樣渲染、照樣沒有錯誤，只是少了資料 ——
  它不會告訴你。

  假的是**資料**，不是版面 —— 渲染的仍然是真正的 `Submit.tsx`。這跟手寫 harness
  的差別就在這裡：harness 假的是結構，而結構正是你要驗的東西。

  真的連跑都跑不起來時，退而求其次是**從原始碼導出結構**，例如：

  ```bash
  awk '/^  return \(/,0' src/pages/Submit.tsx | grep -oE '<(textarea|label|div className="[a-z-]+")'
  ```

  那份 dump 一眼就看到兩個 `textarea`，也順便揭露了錯誤訊息被排在整頁最後面
  （送出鍵早就搬進輸入列了，送出失敗的人根本看不到那行字）—— 那個盯著截圖
  看三次都沒發現。

  ⚠️ **但靜態讀取（包含上面那種 dump）看不到條件渲染的區塊。** 2026-09-22：
  在 `MyWorker.tsx` 插一段新內容，讀原始碼與截圖都很合理 —— 因為
  `{issued && …}`（只顯示一次的 `WORKER_TOKEN`）當下不在畫面上，於是那段
  被插進「產生 token 的按鈕」與「token 揭示區塊」中間，把剛發出的、
  **只會出現這一次**的東西擠到下面。看得到它，是因為連 `POST /api/workers`
  也攔下來回一個假 token、**真的按了那顆按鈕**。
  所以：**改一頁之前先列出它有哪些條件分支，把每一個都觸發一次再看版面。**

  🚨 **這台機器量不了中文版面 —— 先驗量測環境本身。**

  `fc-list :lang=zh | wc -l` 回 **0**：一個中文字型都沒有。無頭瀏覽器只好用
  fallback 畫豆腐框，而豆腐框的字寬跟真的中文字差很多：

  | 字級 | 這台機器（豆腐框） | 真實全形中文 | 每字少算 |
  |---|---|---|---|
  | 14px | 8.40 px/字 | 14px（＝一個 em） | **5.60px** |
  | 13px | 7.80 px/字 | 13px | **5.20px** |

  導覽列那排標籤（丟 job／我的 job／帳本／我的 worker／通知／排行榜／登出／
  系統亮暗）**總共被低估 99.2px**（14 個 14px 字 + 4 個 13px 字）。2026-09-22 的實際後果：兩個 session 先後
  量出「內容 702.6、容器 728、餘裕 25px、確認是一行」，而使用者的瀏覽器裡
  真實內容約 804px、**超出 76px、就是兩行**。我們據此做了一個設計決定
  （品牌只留圖示），而那個決定的理由是假的。

  **量之前先跑 `fc-list :lang=zh | wc -l`。** 回 0 的話：

  - 純英數的版面照量沒問題
  - **含中文的寬度一律不可信**。要估的話自己補：`中文字數 × (字級 − 豆腐框字寬)`，
    係數見上表。**字級要逐個元素讀**（`.theme-opt` 是 13px 不是 14px），而且
    **中文字數要從 DOM 的文字節點數**、不要照自己打的字串列表數 ——
    `.sr-only` 的字會出現在 `textContent` 裡但不占寬度，三格切換器就藏了
    「跟隨系統／亮色／暗色」三份。這兩個坑各讓人算錯過一次（145.6 與 101，
    正確是 99.2）。
  - 更好的做法是**在真實 DOM 上補回缺的寬度再重排**（逐個元素加 `padding-right`
    等於它的缺額），這樣量到的是「會不會換行」而不是一個估計數字
  - 真正的量測儀器是**使用者的瀏覽器**。他傳來的一張截圖勝過這裡的任何數字

  這條比其他幾條更根本：前面那些講的是「驗證的方法要對」，這條講的是
  **驗證的儀器要先校準**。儀器壞掉時，方法再嚴謹也只是把錯的數字量得更精確。

  ⚠️ **「沒有溢出」不能當成通過條件。** 程式化地走訪元素比對 `getBoundingClientRect()`
  是好工具，但 2026-09-22 那次掃出來的兩個問題**都不是溢出** —— 按鈕被擠到容器
  **內部**、四個字直排成一行一個字，邊界全部合法。眼睛還是得看。
- **補的測試本身也要驗兩件事** —— 一個不會失敗的測試比沒有測試危險，
  因為沒有測試至少誠實，而它是在主動製造安全感。兩種失敗方式是一體兩面，
  2026-09-22 兩種各發生一次：

  | 它會不會**永遠綠**？ | 把被保護的東西改壞，確認它真的紅。`s3_console_url` 的空預設值改成一個網址 → `test_default_is_empty` FAILED（`13b14ba`）|
  |---|---|
  | 它會不會**安靜跳過**？ | `except Exception: pytest.skip()` 把自己的 bug（事件迴圈用錯）吞成「連不到資料庫」，四條測試兩綠兩 skip，看起來像環境限制。只捕捉真正的連線錯誤（`OperationalError`、`OSError`）（`5074539`）|

  跑完看一眼**通過數與跳過數**，不要只看有沒有紅字。

- **外部產品的行為** —— 去查文件或實測，不要憑印象。Cowork 的 session 路徑我們
  猜錯過一次，而那個猜測直接寫進了使用者看的文案。

### 同一類：不要對共用環境做沒驗證過的假設

2026-09-22：有人要關掉自己起的 dev server，跑了 `pkill -f "node.*vite"` ——
那個 pattern 把**使用者正在用的**那台一起殺了，他過了一段時間才發現打不開。

那次其實有現成的線索被忽略：自己起的 vite 自動跳到 **5174**，那就是「5173 已經
被別人佔用」的證據，在跑 pkill 之前就看得到。

- **關 process 記 PID 精確殺**，不要用 pattern 匹配
- 動到**通訊埠、暫存目錄、全域設定**之前，先看那裡是不是已經有別人的東西
- 這跟「輸出要真的被執行過一次」是同一件事的兩面：一個是沒驗證輸出，
  一個是沒驗證環境

**這條跟第一條（`git add -A`）的差別**：第一條防的是弄糊歷史，這條防的是
**把假的東西交到使用者手上**。第二種傷害大得多，因為它會被相信。

#### 1. 刪除 worker —— **只有從來沒跑過 job 的才能刪**

現在 `workers.py` 只有 `GET` / `POST` / `POST accepting`，建錯的 worker 永久留著。
使用者測試時會建一堆，這是真的困擾。

**判定是「`Job` 表裡一筆 `worker_id` 都沒有」**，不是「現在沒有進行中的 job」。
後者會讓一台跑過 50 個 job 的機器只要閒著就能被刪掉，那 50 筆的「由 X 代跑」
會斷掉 —— 而那是人情債的依據。

- 判定與刪除要在**同一個交易**裡，不然「檢查完、刪除前」剛好被派一個 job 就出事
- 擋下來的時候**不要只是把按鈕灰掉**，要說為什麼：
  「這台跑過 3 個 job，刪掉會讓那些紀錄失去出租者」
- 跑過 job 的機器目前**沒有**辦法從清單移除，這是已知的洞。**這次不補** ——
  現在還沒有人真的退役過機器，替還沒發生的情境設計正是 §10 一直在避免的事

#### 2. 講清楚 worker 不是 container

使用者原話：「新增一台 worker 後，背後是新建一個 container 嗎？」
**那個疑問本身就是問題** —— 「新增 worker」這顆按鈕讀起來像雲端幫你開了一台機器。

詞已經定在 [`../CONTEXT.md`](../CONTEXT.md)：**worker** 是出租者機器上的常駐程式
加 hub 上那筆註冊；**job 容器**是每個 job 臨時開、跑完即銷毀的那個。

頁面上補一句，大意：「這裡產生的是一組 token。實際接單的是你電腦上跑起來的程式，
每個 job 會另外開一個用完即丟的容器。」

#### 3. 憑證：頁面上現在一個字都沒有

出租者按完「產生 token」，畫面叫他貼進 `.env` —— 然後就沒了。沒有任何地方說
還要設 `CLAUDE_CREDENTIALS`，而少了它 worker 根本跑不起來。

**文件已經寫好了**，頁面只要一個連結加一句話：
「還要設定你的 Claude Code 憑證，見**出借你的額度**（`worker/README.md`）。
懶得一步步做的話跑 `worker/install.sh`。」

不要把步驟抄進頁面 —— §10 的決定（文件而不是互動式引導）仍然成立，缺的是執行，
而執行已經補上了。

#### 4. MinIO 那段補上路徑格式

使用者的原話：「一點開進去似乎會找不到是哪個資料夾」。

**不要重構 key 結構。** 改成 `jobs/<user_id>/<job_id>/` 的代價是 `transcript_key`
與 `artifact_key` 散在 hub 與 worker 各處、既有物件要搬、lifecycle 規則要改 ——
**而且解決不了問題**：一個 job 有借用者與出租者兩個人，路徑只能放一個。

在現有那段 console 說明裡多一句就好：
「路徑是 `jobs/<job id>/`，job id 在該 job 詳情頁的網址列上。」

使用者選了只放這裡、**不要**在 job 詳情頁也放一份。

#### 交付（`5074539`）

**不需要 migration** —— 除了 `jobs.worker_id` 與 `jobs.requested_worker_id`，
沒有別的東西指到 `workers`，沒跑過 job 的那一列直接刪得掉。`models.py` 沒動。

**判定多擋一個 `requested_worker_id`**：有人指名這台、job 還在排隊時
`worker_id` 還是 NULL，只看 `worker_id` 會刪掉一台正被指名的機器，讓那筆 job
指向不存在的 worker。訊息也不同（「有 job 指名這台在排隊」）。

交易：取 worker 那一列時就 `FOR UPDATE` —— 派單那邊設 `Job.worker_id` 時
Postgres 會對這一列拿 `FOR KEY SHARE`，兩者互斥。外鍵是最後一道防線，
撞上回 409 不是 500。

列表多回 `job_count`，**只給自己的 worker** —— 別人幫誰跑過幾次不該出現在
別人的畫面上，那跟額度紅綠燈的粗略分寸是兩回事。

憑證那句寫的是**檔案路徑不是連結**：出租者手上本來就有這份 repo，
worker 就是從那裡跑起來的；寫 GitHub 網址等於在前端寫死一個會過期的東西。

#### 🚨 測試檔可以跑真的資料庫，但有兩個坑（`5074539` 踩過）

`hub/tests/` 以前全是純函式測試，這是第一個碰資料庫的。兩件事寫在這裡免得重踩：

1. **每個測試自己開一個 `NullPool` 的 engine。** 共用 `app.db.engine` 的話，
   它的連線池會留著上一個測試的事件迴圈，第二個測試起就會拿到
   「attached to a different loop」。
2. **`except Exception: pytest.skip()` 會把那個錯誤吞成「沒有資料庫」。**
   第一版就是這樣：四條測試兩條綠兩條 skip，看起來像環境問題，其實是程式壞了。
   只捕捉 `OperationalError` 與 `OSError`。

交易包住整個測試、結束 `rollback`，所以不會弄髒開發用的資料庫。
非同步測試用 anyio 的 plugin（隨 anyio 裝的），沒有為此多加一個開發相依。

### → session A：代跑者用長期 token 出借額度（2026-09-22 指派）

**方向大改，先讀這段再看細節。** 原本的模型是「每位代跑者在自己的機器上跑 worker，
憑證不離開他的機器」。使用者決定改成：**沒有人安裝任何東西，所有 job 都跑在這台
主機上，代跑者交出一組長期 token。**

關鍵發現（使用者實測）：`claude setup-token` 會產生 **一年期**的 OAuth token
（`sk-ant-oat01-…`），用法是環境變數 `CLAUDE_CODE_OAUTH_TOKEN`。這一口氣解掉了
原本擋路的三件事：8 小時過期、唯讀掛載寫不回刷新後的 token、共用主機上沒有人
會刷新它。**而且那是 Anthropic 官方為非互動場景設計的通道，不是我們在繞路。**

`.claude/rules/security.md` **紅線 2 已為此修訂**（`7199b0e`）—— 動手前讀它，
五條約束每一條都不可省。

#### 🚦 第一步是 spike，沒過就不要往下做

使用者的決定是「**先證明它會動，再重構**」。到目前為止**還沒有任何一個 job 是用
`CLAUDE_CODE_OAUTH_TOKEN` 跑起來的**，那條路上還有未知。

拿一組 token，照 `run-job.sh` 現在的形狀跑一次，但**拿掉 `.credentials.json` 的
掛載、改成環境變數**，確認四件事：

1. 乾淨 HOME + 只有那個環境變數，`claude -p` 認證得過
2. `--settings '{"availableModels": …}'` 的 model 白名單還有效
3. `--max-budget-usd` 還有效
4. 回傳的 `total_cost_usd` 還在 —— **人情債整個帳靠它**，沒有它這條路就不能走

四件有任何一件不成立就停下來回報，不要自己想辦法繞。

#### 🚨 五件不可省的（全在紅線 2 裡）

- **絕不進 log。** 派單 payload 現在含 token —— worker 那邊有 `print` 在印 job

一個 worker 服務所有代跑者是對的方向（token 變成環境變數之後，「一人一個 worker

### → A 與 C：託管模型的第一階段（2026-09-22 指派，**先讀完整段再動**）

使用者看著「我的 worker」頁問：「實際代跑者的使用情境是什麼？不是說大家都用同一個
worker 嗎？代跑者只是給我們 token 就好嗎？」—— **三個問題都指向同一件事：那一頁
在描述一個已經被取代的架構**（那段文案是 2026-09-22 早上派工寫的，寫在方向轉彎之前）。

grill 之後定案的代跑者情境，**就是他問的那麼簡單**：

> 登入網頁 → 授權一次 → 結束。不開機、不裝東西、不讓筆電開著。
> 之後他只需要偶爾看帳本、去收飲料。

#### 🚦 spike 先行：`setup-token` 能不能自動化（A）

使用者選了「**頁面驅動授權**」而不是「自己貼 token」。理由是今天的實際教訓：
**只要那串東西需要人類複製貼上，它就會出現在剪貼簿、瀏覽器歷史、對話紀錄、
截圖裡** —— 今天真的發生過一次。

要確認的：後端能不能用 pty 跑 `claude setup-token`、解析它印出的授權網址、
等它完成並取回 token。（直接在容器裡跑會沒有輸出然後 timeout，我試過。）

**不可行就回報，不要自己改成「請使用者貼上」** —— 那是另一個決定，要使用者點頭，
而且 UI 的份量完全不同（那時必須把「一年有效、外洩沒有止血點」講得很重）。

#### 三件已經定案的結構改變

**1. 一位代跑者一筆，不是清單。** 舊模型下「多筆」對應「我有桌機和筆電」；
新模型下他只有一個 Claude 帳號。那一頁從「清單 + 新增一台」變成**單一表單**：
沒授權就顯示「開始出借」，授權過就顯示條件與狀態。

**2. 🚨 三個控制項會憑空消失，必須搬進網頁。** 這是查證時撞出來的，沒有人提過。
代跑者現在能控制**每個 job 的花費上限、可用 model、要不要開放外網** ——
它們全在他自己機器的 `worker/.env`（`JOB_BUDGET_USD`、`AVAILABLE_MODELS`、
`ALLOW_FULL_NETWORK`），worker 註冊時回報給 hub。

**新模型下他沒有機器，也就沒有 `.env`。** 不搬的話這三個控制項直接消失 ——
而那正是「把額度借出去」讓人敢做的原因。`JOB_BUDGET_USD` 的註解自己寫著
「一個 Opus job 八分鐘能燒掉 US$25」，**那是代跑者的錢**。

這也給了那一頁新的存在理由：它從「產生 token 給你的機器用」變成**「你出借的條件」**。

**3. 詞彙全面改版**（`CONTEXT.md` 已更新，`7c51a71`）：

| 舊 | 新 | 說明 |
|---|---|---|
| 出租者 | **代跑者** | 「出租」是租借帳號的語彙，而這個系統刻意不是那件事 |
| 借用者 | **委託者** | |
| 我的 worker（分頁） | **我來代跑** | 跟「丟 job」對稱，都是動詞 |
| 我的 worker（那筆記錄） | **出借設定** | 他沒有機器，他有的是一組條件 |
| worker | *（不對使用者使用）* | 退回主機維運語境：站台上那個領單的常駐程式，只有一個 |

**只改使用者看得到的**（`web/src/**` 的 UI 文字、`worker/README.md`）。
SPEC.md、程式碼註解、這塊板子**維持舊詞不動** —— 它們記錄的是當時的決策。

#### ⏳ 一件要跟 token 綁在同一筆交付的待辦

A 在 spike #8 抓到的：**新模型下 job 跑在共用主機，代跑者反而看不到內容了，
看得到的是主機管理者。** 而提交頁那個隱私勾選現在**點名代跑者** —— 一個看不到的人。

**現在不要改**（今天的 job 確實還跑在代跑者機器上，改了立刻變成謊話），
但它**必須跟 token 那條路同一筆上線**，不能分開。

#### 🚨 後端 commit 了不等於上線了（2026-09-22）

`89889c4` 之後，提交頁的代跑者下拉指到 `GET /api/workers/lenders`，但 **8787 上

**重啟之前先在另一個 port 把新碼跑起來。** 這一輪 `2da7e02` 加了

8799 確認 healthz 與路由表，換掉「停掉之後才發現起不來」。

#### 前端與後端的欄位，可以用 `/openapi.json` 逐欄位比

### → session C：MinIO console 改成只給主機管理者（2026-09-22 指派）

C 指出的前提失效是對的：那段當初能放在出租者頁，理由是「**只有出租者看得到，
而出租者是 RD、手上已經有更敏感的東西**」。新模型下代跑者只是**授權過的人，
不必然有主機權限、也不必然是 RD** —— 前提沒了，結論不能自動留著。

使用者選了「移到只有管理者看得到的地方」。**系統目前完全沒有 admin 概念**
（查過：hub 沒有任何 role 欄位，Observ 只回 `id` 與 `email`，沒有群組可用），
所以這個角色要我們自己定義。以下四項已定案：

**1. `ADMIN_EMAILS` 環境變數判定**（`hub/.env`，逗號分隔）。不加資料庫欄位、
不用 migration、不做管理介面 —— 跟 `TEAMS_CHANNEL_NAME` / `S3_CONSOLE_URL`
同一個模式。admin 大概一兩個人，替「將來要在網頁上指派管理員」做設計，
正是 `web-spec §10` 一直在避免的事。

**2. 🚨 `s3_console_url` 只回傳給 admin。** 現在它對所有人都出現在 `/me` 裡 ——
就算前端不渲染，那個網址仍然送到了每個人的瀏覽器。**不是 admin 就根本不給**，
那比「拿到了但不顯示」紮實一個等級。`/me` 同時多一個 `is_admin: bool`。

**3. 不加新分頁。** 做成「我來代跑」頁底部一個 admin 才看得到的區塊。導覽列
餘裕只剩約 25px，而**這台機器量不了中文寬度** —— 現在去動導覽列是拿一個量不準
的東西冒險。

**4. 文案維持現在那段**（整站共用 bucket、沒有「只看自己」的權限、你會看到
別人的對話與檔案）。對 admin 講那句話仍然成立，而且他更該知道。

#### 驗證

- **三種身分都要渲染過**：admin、非 admin 的代跑者、非 admin 的委託者。
  非 admin 那兩種要確認**網路回應裡根本沒有那個網址**，不是只看畫面上沒有 ——
  打開 devtools 看 `/me` 的 payload，或在攔截層檢查

- 照板子：`fc-list :lang=zh` 回 0，不對中文寬度下結論

### ~~3. 附件上傳~~ — 2026-09-22 由 session B 交付，**UI 已接**（`087c15a`）

**取票 →** `POST /api/uploads/attachment`，body `{ "filename": "報表.xlsx" }`
回 `{ key, put_url, max_bytes }`。一次一個檔，要傳多個就呼叫多次。
檔名由 Hub 淨化（去路徑、去 `..`）後放進 key —— 那個 key 最後會變成容器裡的
檔案路徑，讓使用者控制那段等於讓他寫到工作目錄外。

**送件 →** 瀏覽器直接 PUT 進 `put_url`（不經過 Hub，跟 `.jsonl` 同一條路）。

**建立 job →** `POST /api/jobs` 的 `attachment_keys: string[]`（最多 20 個）。

| 限制 | 值 | 錯誤碼 |
|---|---|---|
| 單檔 | 50 MB | `413` |
| 附件合計 | 50 MB | `413` |
| 單一 job 輸入合計（含 transcript） | 100 MB | `413` |
| 空檔案 | — | `400` |
| 同一個 key 帶兩次 | — | `400` |
| 不是你的 / 不存在 | — | `404`（**訊息相同**） |

最後一列是刻意的：分開講等於給人探測別人 job id 的工具。

**worker**：把附件放進工作目錄**根層**（不是子目錄）—— Claude 一進去就該看到
它們，這些是 job 的標的。同名檔會加序號（`a.pdf`、`a-2.pdf`），不互相覆蓋。

#### 🔑 誰負責去重：**UI 決定，worker 只是防呆**

worker 的序號迴圈要留著（兩個分頁、重送、race 都還是會撞，後端不能沒有防線），
但**正常路徑下它應該永遠不會真的改到名字**。

理由是 **worker 的改名是隱形的**。使用者從兩個資料夾各挑一個 `report.pdf`，
job 裡變成 `report.pdf` 與 `report-2.pdf`；Claude 在回答裡會用後面那個名字稱呼它，
改過的話也以 `report-2.pdf` 回到產出清單 —— 而使用者從頭到尾沒看過這個名字，
也沒有任何地方告訴他發生了改名。

UI 可以直接避免：`filename` 是客戶端送的（`POST /api/uploads/attachment` 的 body），
所以瀏覽器在使用者挑檔的當下就能發現撞名，當場講「你已經有一個 report.pdf，
這個會存成 report-2.pdf」或讓他自己改名。挑檔那一秒就知道，勝過事後從產出清單反推。

**契約**：`filename` 由客戶端保證不重複；worker 的序號是防呆，不是功能。
沒寫這一句的話兩邊都以為對方會處理，結果是使用者收到一個他沒命名過的檔案。

#### 🔑 那題的結論：改過的輸入檔會回傳，沒改的不會

用**內容雜湊**比對（放進工作目錄時記 sha256，收成果時再比一次）。

- 照檔名排除 → 「幫我改這份簡報」會**什麼都拿不到**，而那是主要情境之一
- 全部回傳 → 五份沒動過的 PDF 會出現在「產出的檔案」裡，變成噪音
- 用 mtime → 有些工具會原樣重寫檔案，會誤判成「改過」

**UI 文案可以這樣寫**：產出清單只會出現新檔案與被改過的檔案；
使用者原樣傳進去的東西不會再回來一次（他本來就有）。
